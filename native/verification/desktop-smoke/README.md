# 真实桌面集成验证

此验证项目引用生产 `Hongguo.Desktop`，在自己的 WPF Dispatcher 中创建真实 `MainWindow`，通过应用内反射调用其现有方法和控件；不使用系统输入、UIAutomation 或浏览器。

```powershell
dotnet run --project DesktopSmoke.csproj -c Release -p:GenerateSupportedTargetFrameworkAlias=false -- '.\sdk-report.json' '全球死考'
```

开发环境要求 Windows x64、.NET 9 SDK，以及已经构建的内嵌 Go bridge 和播放器运行库。验证窗口透明且不显示在任务栏；所有检查直接调用应用对象。

验证独立使用 `state/<时间>/` 配置目录；若现有用户配置含匿名设备配置，会复制到此目录复用，不修改原来的观看记录。该目录已忽略，配置值不写入报告。

输出位于 `results/desktop-smoke.json` 和相应 PNG。PNG 由 WPF RenderTargetBitmap 生成，仅供窗口布局审查，不包含原生视频 HWND 的画面。真实播放依据 libmpv 状态、视频尺寸、时长和自然 EOF 事件验证。每项等待上限为 60 秒。

## 扩展验证

后续版本额外覆盖以下行为，实际通过情况以最新 JSON 为准：

- 记录目录首项显示时间，以及目录加载完成时后台补图是否仍在进行；等待补图后记录封面更新通知和最终覆盖数。
- 切换综合、剧集、视频三个搜索分类，保存完整结果 ID；加载第二页并去重合并，与独立直接 SDK 诊断报告中的同关键词、同分类、同页游标比较。
- 对 `SpeedCombo` 和 `QualityCombo` 的 `PART_Popup.Child` 单独生成 PNG，核验下拉列表的暗色背景和明亮前景；无需系统 GUI 输入。
- 选择服务端实际提供的最低高度画质，验证重新解码的高度匹配，同时保留 16 秒进度、暂停、1.5 倍速及 37% 音量。
- 观看记录使用 WrapPanel，并验证至少两张封面实际解码、前两张卡片在同一行并排显示。

第一个命令参数为历史直接 SDK 诊断 JSON，第二个为关键词。SDK 报告需要 `calls` 数组，每项包括 `query`、`tab`、`page`、`sdk_cursor`、`sdk_has_more` 和 `items[].id`。历史报告可能使用不同匿名设备、不同时间，其结果差异仅作为 observation 保留，不计为产品失败。

严格的搜索检查使用同一次真实响应：测试短暂持有自己后台对象的发送锁，在请求创建后取得该请求的 pending 完成任务，立即释放锁，直接观察原始响应。随后核验界面展示的首屏、第二页去重合并 ID 与游标；不修改生产请求、响应或生产代码，不增加业务 API 请求。

