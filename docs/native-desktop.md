# 红果原生桌面版 1.0

本说明对应 **2026-11-09 更新的 1.0** 桌面版，发行入口为 [GitHub v1.0](https://github.com/shenxiaobei/openhongguo-desktop/releases/tag/v1.0)，本地运行入口统一为源码同级的 `Releases/v1.0/红果原生桌面版.exe`。本次发布范围包含原生滚动弹幕、播放保护状态误判修复、最高画质选择及缩小呈现优化，复用此前验证过的当前 EXE。软件基于并借鉴 [beilunyang/openhongguo](https://github.com/beilunyang/openhongguo) 二次开发，保留原作者版权与许可证。

下文按日期保留历史实现和验证范围，其中 2026-11-07、2026-11-08 的「仅本地」「未发布」描述对应当时阶段。当前下载文件以发行页、更新日期和 SHA256 清单核对，产品版本继续为 **1.0**。

当前版隐藏标题文字和标题栏左侧的小图标，保留原生标题栏的拖动区域及最小化、最大化、关闭按钮。窗口内全屏仍保留标题栏，F11 屏幕全屏隐藏整条标题栏；不修改 EXE 文件图标，保留窗口大图标供任务栏使用。

标题栏净化、浮层层级、历史顺序与搜索联想修订日期为 2026-11-06（Asia/Taipei）。2026-11-07 的本地源码增加保留全部画面的拉伸铺满、当前画质信息、官网评论预览及原生滚动弹幕，并修正屏幕全屏边界。本地交付只使用 `Releases/v1.0/` 中的一份 EXE，旧预览和旧软件 ZIP 从交付目录清理，源码、许可证、构建运行库及历史验证证据保留。图标重设计按用户要求暂停。

Windows 10/11 x64 原生窗口，视频直接嵌入程序。双击 `红果原生桌面版.exe` 使用；程序包含 .NET 桌面运行时、SDK 和视频解码组件，不需要另装 Edge、mpv、ffplay、ffmpeg 或 .NET。

## 使用

1. 双击 EXE，在「发现」页浏览或搜索剧名。输入停顿约 300 ms 后显示最多 8 条联想；↑ / ↓ 选择，Enter 搜索选中词，未选词时搜索当前输入，也可直接点击候选。Esc 收起列表。
2. 点击卡片自动播放，右侧可直接选集。
3. 主栏提供进度、播放/暂停、上一集/下一集、时间和全屏按钮；普通模式位于画面下方，沉浸模式为顶部短浮条。点击齿轮打开紧凑「播放设置」菜单：倍速、画质和画面模式各占一行，右侧显示当前值，点击后在同一面板内选择；自动连播开关和音量也各占一行。宽窗还可在主栏调整音量。画质只列出当前分集实际提供的档位，默认最高画质，切换保留进度和暂停状态；画质选项页上方显示实际播放档位、解码分辨率与接口片源码率。默认开启「自动连播」，支持下一集及同系列下一季。
4. 「连续推荐」支持视频区域滚轮或 ↑ / ↓ 切换另一部剧，队列继续获取后续推荐；一部剧内仍按自动下一集设置连播。
5. 空格暂停，← / → 快退或快进 5 秒。主栏全屏按钮切换「窗口内全屏」：保留窗口大小、位置和系统标题栏，隐藏播放标题及侧栏，视频宿主使用全部客户区。右上角最大化按钮按系统工作区扩大窗口并保留标题栏；F11 或双击画面进入屏幕全屏并隐藏系统标题栏。进入这三种状态时沿用当前画面模式。设置菜单打开时，Esc 先收起菜单；随后 Esc 先退出屏幕全屏，再退出窗口内全屏。
6. 关闭窗口保存观看进度并结束本窗口创建的 SDK 进程。
7. 「排行榜」每部剧占一整行，纵向依次展示名次、封面、完整剧名、集数和平台实际提供的热度。顶部两排横向标签分别切换作品类型、平台榜单，选项较多时可横向滚动；右侧「分类」展开主题、人物设定、故事背景，可组合选择。题材模式按平台热度排序，数字为当前列表序号；点击「全部题材」回到原平台榜单，平台榜的数字取实际名次，「荐」为推荐位。两种模式均支持加载更多、点击整行观看及返回保留列表。推荐榜会按当前匿名设备返回内容，热播榜更适合找热门作品。
8. 「按题材找剧」读取平台真实的体裁、主题、设定、背景、排序、受众和时间条件，可组合筛选并翻页。例如悬疑属于主题、重生属于设定；电影和搜索保留各自的接口。
9. 播放页右侧展示平台实际返回的播放、追剧、本集点赞和评论数量，未返回的值显示「—」。点击「评论与弹幕」读取官网公开评论预览，显示实际预览条数与官网总数；官网预览没有完整分页。弹幕标签保留时间轴列表和点击定位，视频内同时可显示真实滚动弹幕，并随播放自动读取后续时间段。关闭讨论区不影响已开启的滚动弹幕。收藏量仍未返回，追剧数与收藏数分开处理。
10. 点击主栏「弹」或按 D 快速开关滚动弹幕；在「齿轮 → 弹幕」调整顶部 1/4 / 半屏 / 全屏范围、小中大字号、20%–100% 不透明度、滚动速度及密度。默认开启、半屏、中号字、85% 不透明度；全屏范围仍留出底部字幕空间。偏好本地保存，暂停、拖动进度和视频倍速均与弹幕时间轴同步。极窄窗口收起主栏快捷开关，齿轮中始终保留入口。

新版采用统一的深色影院界面，播放时收起导航与搜索。普通模式使用 44 DIP 高的单行主栏，进度与按钮排在同一行；倍速、画质、画面模式、弹幕与连播收进齿轮设置，窄窗的音量也从设置调整。时间、上一集及主栏音量按可用宽度收拢，播放、下一集、设置和全屏入口保留。设置菜单宽约 240 DIP，高度随内容自然测量；选项页保留当前勾选标记与返回入口。选集继续通过独立浮层打开，菜单均为深色样式。

窗口内全屏和屏幕全屏取消固定底部控制带，视频宿主使用全部客户区，不因主控隐藏而留出额外空白。顶部控件层底板和边框 alpha 均为 0，只为控件内容保留轻微黑色阴影以提高辨识度，不再绘制整块底板。布局高 44 DIP、宽度最多 860 DIP，通常距顶部 12 DIP，主控远离底部字幕区域。普通模式位于画面下方的底栏保持原样，齿轮设置弹层继续使用可读的深色底；约 3 秒隐藏规则不变。透明底板不代表按钮和进度线本身不可见，也不保证视频中任意位置的烧录文字都无遮挡。控件显隐不改变视频布局，进入或退出沉浸模式、调整窗口大小时再适配可用区域。「全屏」只控制播放区域布局；调整窗口宽高、进入全屏或系统最大化时，沿用所选画面模式。

「齿轮 → 画面模式」提供两种保留全部画面的选项：默认「完整显示」保持原始比例，片源与窗口比例不同时保留黑边；「拉伸铺满」按当前窗口比例分别缩放横纵方向，铺满视频区域并保留烧录字幕，人物比例可能随窗口变化。原来的裁切入口已替换，两种模式均不裁切边缘。当前与预加载播放器保持同步，窗口缩放、全屏切换、最大化及下一集交接都沿用所选模式；重新打开程序默认完整显示。

「齿轮 → 画质」中，「最高画质」按片源完整尺寸的短边排序，再取较高码率的流，以相同规则比较横屏与竖屏内容；尺寸缺失时使用高度、档位标签等兼容回退。手动指定同一档位时也选择匹配流中较高分辨率及码率的一条。当前信息优先读取解码器的真实视频尺寸，首帧未就绪时回退到接口片源尺寸；码率标为片源码率，取接口元数据。窗口拉伸后的显示尺寸不当作片源分辨率。清晰度仍受原始压缩、码率及显示放大影响，1080p 标签不保证手机与电脑观感一致。

SDK 完整解析普通 `video_list` 与 `dynamic_video` 两组，比较各组的 `best`，按实际尺寸的短边分辨率、同档码率选择较高的一整组；尺寸缺失时沿用前述兼容回退，平手保留普通组。视频、音轨及保护信息始终来自同组，不交叉拼接。普通组无有效地址时可采用动态组；普通组可用时，损坏的动态组不影响其播放。最高只指当前接口返回的可用候选，不代表所有客户端可能开放的片源，也不证明 iPhone 使用相同码流。播放信息另保留精确毫秒时长，供片尾弹幕与时间段请求使用，旧整数秒字段继续兼容。

2026-11-08 本地渲染修订：缩小滤镜从随包库默认的 Hermite 改为 `dscale=ewa_lanczossharp`、`dscale-antiring=1`，减少窗口小于片源时细线与纹理的额外柔化，并抑制高反差边缘的振铃。当前和预加载播放器使用同一构造设置；媒体选流、原尺寸显示、放大滤镜及颜色设置保持原样，不添加锐化、降噪或转码。片源地址直接交给内嵌 libmpv 解码，缓存和解密不会重新压缩视频。该调整改善缩小呈现，片源已丢失的细节仍受限制；没有证明手机与桌面使用相同视频文件。对照及验证证据位于 `%USERPROFILE%\.codex\artifacts\openhongguo\project-evidence\render-quality-2026-11-08\`。

本轮对照包含 40 项初筛、22 项仅缩小参数检查和最终 4 项原尺寸/放大不变验证；静态 RGB 的原尺寸输出逐像素相同。另对真实 HEVC 同一集暂停在 88.9 秒，软硬解码、1:1 与 1658×933、旧新缩小参数共 8 项通过：软硬解码截图逐像素一致，1:1 原尺寸截图与输出最大仅差 1/255，缩小后的细节改善较轻微。现有画质/预加载回归 8 项及真实二季 183→184 的结束事件续播均通过。测试使用隔离配置及原生离屏输出，不代表手机同源比较、所有显卡性能或桌面目视验收。

2026-11-08 再次排查「播放信息暂不可用」已确认通用解析错误：部分明文片源只有普通 `gear_des_key` 描述和 `check_info` 完整性校验，没有加密标记；原实现把这些元数据当成加密证据，随后对不存在的密钥解包而失败。现根据明确的 `encrypt`、加密方式、密钥标识、包装密钥或描述中编号 `1` 字段的加密枚举判断；普通描述和校验信息不再单独触发加密。普通组与动态组共用规则，不含剧名或集数特判，最高分辨率及同档最高码率选择保持不变。加密模型结构损坏或存在未知非空保护标记时仍保守处理；失败模型不进入缓存，显式重试重新获取。

前一轮只修复失败模型缓存，并测试了《全球死考：刚下刑场你让我去考试一季》第 12 集，未对应用户实际播放的二季，因而没有解决现场首次加载失败。本轮在二季（系列 ID `7703760419889876030`、250 集）第 183 集保留了旧桥稳定失败基线；修后用隔离配置、生产窗口和 JSONL 桥验证第 12、183、184 集，真实 libmpv 均解出 1920×1080 首帧并推进进度。183 集准备好下一集后，定位至片尾再由真实结束事件自动交接 184 集也通过。该验证检查真实媒体解码及生产调用链，未包含系统桌面合成或人工点击；后续服务端不可用等其他原因仍需根据具体响应排查。脱敏证据位于 `%USERPROFILE%\.codex\artifacts\openhongguo\project-evidence\episode183-fix-2026-11-08\`。

加密对照《谁让这个文盲修仙的第三季》第 3 集同样通过真实首帧和进度验证，选择当前接口最高的 1920×1080、1,167,085 bit/s，并确认所需媒体密钥存在。离线保护矩阵覆盖 45 种字段组合在普通组、动态组中的 90 个叶子用例，另验证默认、best、指定 1080p 均保留最高分辨率及同档最高码率、组间切换不混用音轨与密钥上下文。协议、SDK、媒体模型和桥接四包测试与静态检查均通过。全部线上验证使用隔离配置，测试窗口自然关闭并清除临时配置；本轮只替换本地 1.0，未同步 GitHub。

滚动弹幕由内嵌 mpv 的内存 ASS 字幕轨渲染，位置与事件起止时间由播放器统一驱动。文字在视频表面内显示，不另建跨应用置顶层；暂停时冻结，跳转时显示对应时间段，倍速时随媒体时间推进。行道不足时跳过该条，不把过期文字堆积到后面。滚动层独立于右侧讨论区预取时间段，来源受限或失败时保留已读内容并允许重试。交互参考 DPlayer，渲染器为本项目独立实现；数据端点、参考链接与设置说明见[评论和滚动弹幕](discussion-api.md)。

弹幕开启期间临时使用主软字幕轨，片源的可选软字幕会暂时切走；关闭弹幕后恢复原选中轨及字幕可见性、样式覆盖、延迟和速度参数。视频自带的烧录字幕不受影响；当前未同时显示主软字幕与滚动弹幕。

沉浸播放中，鼠标接近顶部 76 DIP 或底部 64 DIP 热区时展开顶部操作栏，中央移动只恢复鼠标；操作播放快捷键也会显示控制栏。静止约 3 秒后控制栏与鼠标一起隐藏，拖动进度、悬停控制区、展开菜单或使用键盘在控制栏内操作时保持可见。设置面板从顶部浮条向下展开，普通模式从底栏向上展开，并按客户区限制尺寸；F11 继续切换屏幕全屏。DIP 是 Windows 逻辑尺寸，实际像素高度随系统显示缩放变化。

控制浮条、设置和选集均为归属播放器主窗口的普通浮层，不使用跨应用系统置顶。展开及计时路径除 WPF 激活状态外，还核对真实系统前台是否属于本播放器；跨进程失活时从原生通知收回浮层。切换到其他应用、最小化或隐藏播放器时收起控制浮层、设置菜单及下拉框，并恢复鼠标；后台鼠标活动或延迟事件不会据此重新打开浮层。回到播放器前台后恢复正常交互，退出沉浸播放时恢复普通窗口的控制区。本次原生层级修订的验证结果以随包记录为准。

应用不设置窗口最小宽高，可以继续拖小；原生标题栏仍遵循 Windows 的系统边界。播放页直接跟随实际可用视口缩放，不保留固定大画布或整窗滚动条；调整宽高时完整显示按原比例缩放，拉伸铺满按窗口比例缩放，均保留全部画面，进度和主要按钮留在窗口内，极矮窗口收起次要标题信息。窄窗导航自动收成图标，悬停显示名称；播放器收起固定右侧栏，通过顶部「选集」打开浮层。重新放大或进入全屏会恢复相应布局。

开启自动连播时，应用会在当前集播放期间提前取得下一集的播放信息，由第二个内嵌播放器静音、暂停地缓冲媒体并准备首帧。前向缓存限制约 12 秒及 24 MiB；缓存达到至少 2 秒、或已读完、或达到字节阈值，且首帧和画面参数均就绪时，切集直接交换已经准备好的播放器。已准备好的切集不再等待原播放器重新联网和解码；URL 过期、准备不足或失败时正常加载。手动切集、切换画质的媒体加载也不再先等待旧播放记录写入完成。记录在切换时立即捕获快照，再按全局队列顺序写入，媒体请求继续并行，避免连续切集时旧记录晚到而覆盖新进度；单条保存失败不阻断后续记录。导航清空当前剧集后，关闭窗口仍等待已排入的记录完成。关闭自动连播、切换其他剧集或退出会取消旧准备；额外播放器会增加一定内存和解码开销。

视频缓冲放在内存中，程序明确关闭 `cache-on-disk`。每个播放器的前向数据上限为 24 MiB，另有 4 MiB 回退缓存；约 12 秒是预读目标，不是整个应用内存用量，解码帧、音频和 GPU 另占空间。切集交接会停止旧播放器，换剧、取消预加载和关闭连播会停止相应准备，退出销毁两个解码器。媒体数据随停止/销毁释放，不会每集写出一个视频缓存文件；进程工作集不一定立即回落。

封面图片另存于 `%LOCALAPPDATA%\OpenHongguo\covers`，目前 24 小时仅控制是否复用，不代表自动删除过期文件，也没有总量清理策略。`%LOCALAPPDATA%\OpenHongguo\native` 和 .NET 单文件解包位置存放运行组件，旧版本也可能保留。首页目录缓存与观看记录在 `%APPDATA%\openhongguo`；首页缓存覆盖同一文件，观看记录长期保存。这些持久文件与内存中的视频预加载不同，本次不新增磁盘清理功能。

播放器默认完整显示，竖屏短剧和横屏内容均按原比例适应窗口，空余区域保留黑边；主动选择「拉伸铺满」后，全部画面按窗口比例铺满，缩放、全屏及切集保持该选择。卡片使用接口实际返回的系列海报，内置 HEIC 解码，不再用分集截图替代。目录先显示、海报后台补齐；再次打开优先显示最近缓存并更新。连续推荐使用发现分页、热门目录和相关推荐接口；内容由服务端返回。发现或推荐明确返回空内容错误时，应用尝试同频道的真实可用目录，并显示来源，例如「热门目录（推荐暂不可用）」。正常分页结束不会重新开启其他来源，电影也不会混入短剧。

连续推荐的队列和分页按频道分别管理，打开自己的推荐候选时保持请求有效，加载期间不接受重复切换。只有平台明确返回内容不可用的候选才会跳过，一次最多尝试五部、读取一页；设备拒绝、账号验证、限流和网络错误保留原提示并停止，避免反复重试。

多季作品会在播放期间读取平台官方系列剧关联，并核对各季的非空合集 ID、季序号和实际分集。开启「自动连播」后，当前季确认完结且最后一集播放结束，才接续准确的下一季，从第一集开始；连续推荐模式也优先接同系列。相似剧名不作为续季依据，缺季、下一季预告未上线、第一集受限或关联冲突时停止并显示原因。关闭自动连播就保持当前集；导航或换剧会取消旧的季列表查询。已有的媒体预加载用于同一季的下一集，跨季目前预取关联信息，切季时仍需加载下一季媒体。

搜索默认「剧集」，可显式切换「综合」「视频」。联想复用 SDK 的真实 `Suggest` 接口，不用搜索第一页猜测补齐；输入停顿约 300 ms 才请求，最多显示 8 条，在内存中缓存最近的前缀结果，旧词响应不会覆盖新输入。中文输入法组合期间不提交联想；失焦、切换应用、移动或缩放窗口、进入播放及关闭时收起候选。联想为空、失败或稍慢时仍可按 Enter 直接搜索原词。服务端建议可能是剧名、主题或其他相关搜索词，不保证词条都对应完整剧集，也不代表所有资源均已收录。新关键词、分类、刷新都回到顶部，加载更多保留当前位置；结果与分页参数来自原 SDK。观看记录以带封面的卡片并列展示。内置桥的状态版本统一为 `1.0-native.1`，桌面产品版本仍为 `1.0`。

## 单 EXE 的工作方式

对外只需复制一个 EXE。程序首次运行自动将内置 SDK 桥、libmpv 和 Vulkan 组件校验并释放至 `%LOCALAPPDATA%\OpenHongguo\native\版本标识`；.NET 与图片解码原生库由单文件运行时自动解包。随后在进程内加载视频库、以私有标准输入输出管道连接 SDK 子进程。此设计不创建本地 HTTP 服务，不启动浏览器，不要求用户安装外部工具。

匿名设备和观看记录沿用 `%APPDATA%\openhongguo\anonymous.json`、`history.json`。诊断日志只记录错误类型和接口方法，不记录播放密钥或完整媒体地址。此版本与旧浏览器入口分开，建议从新名称的 EXE 启动。

弹幕显示偏好保存在同目录 `danmaku-settings.json`。评论正文、弹幕条目及 ASS 时间轴只留在内存，退出后释放，不创建磁盘弹幕缓存或评论数据库。

弹幕采用中性灰 `#D5D9DC` 字面、半透明细描边和轻阴影，按媒体时间渐入 220 ms、淡出 300 ms。视频实际显示高度达到 540 像素时，中号字使用 ASS 字号 26，低于该高度使用 29，行道间距仍按 29 保留；这是 720 高的 ASS 画布字号，显示时由播放器缩放。小号、大号和用户保存的不透明度等设置保持原样，文字边缘轻微柔化。

标准弹幕速度较首版降低约三分之一，同一句文字停留时间增加约50%；慢速和快速档也同步放缓。拖动进度时回看18秒内的时间段，覆盖慢速下仍在画面里的文字。

网络和内容接口仍使用 openhongguo 原有匿名 SDK。服务端要求账号、验证或未返回内容时，界面显示对应错误并提供重试入口。单 EXE 打包解决本机依赖；远端接口的响应仍取决于服务端。
